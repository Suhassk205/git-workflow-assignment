Step 4 Undo Operation using Git [1 Mark]

To demonstrate Git's historical rollback capability, an experimental commit was introduced and subsequently undone:

  • Commit Created: Added debug_config.txt with commit ID b7b8d3e ("Temporary commit: Add debug configuration (to be undone)").
  • Undo Executed: Ran git reset --hard HEAD~1 to roll the HEAD pointer and branch ref back to commit ff41017, purging uncommitted staging and working directory data.
  • State Verified: git log and git status confirmed that the commit was undone, the working tree was left clean, and the repository state was perfectly preserved.
Technical Comparison: git reset vs. git revert
git reset: Rewrites branch history locally. Options: --soft (preserves edits staged), --mixed (default, preserves edits unstaged), --hard (discards edits entirely). Best for unpushed commits.
git revert: Creates an inverse commit that cancels previous changes without rewriting history. Ideal for public/shared branches.

Step 6 Command Documentation File (git_commands.txt) [1 Mark]

The required file git_commands.txt was generated and committed in the repository root. Below is the exact command reference:

Repository Root: git_commands.txt (All Executed Commands & Explanations)
1. git init -b main: Initializes an empty Git repository locally and sets the default branch to 'main'. 2. git status: Inspects the working directory and staging area, reporting tracked, untracked, and modified files. 3. git add <file> / git add .: Stages working tree modifications into the Git index preparing snapshots for commit. 4. git commit -m "<msg>": Permanently records staged snapshots into the repository history with an explanatory message. 5. git diff: Displays line-by-line differences between modified files in working directory and staging or last commit. 6. git branch <name>: Creates a new isolated branch pointing to the current commit without automatically switching to it. 7. git checkout <branch> / git switch <branch>: Switches HEAD and working directory to the specified branch for development. 8. git branch: Lists all local repository branches and highlights the currently active branch with an asterisk (*). 9. git merge <branch> --no-ff -m "<msg>": Integrates target branch into current branch with a dedicated merge commit. 10. git log --graph --oneline --all: Displays commit history across all branches in a visual ASCII graph format. 11. git reset --hard HEAD~1: Undoes the latest commit, moving HEAD back by 1 and discarding staged/working tree edits. 12. git remote add origin <url>: Associates the local repository with the remote repository on GitHub under alias 'origin'. 13. git remote -v: Lists all configured remote aliases and their corresponding fetch and push URLs. 14. git push -u origin main: Pushes local 'main' commits to GitHub and sets upstream tracking reference. 15. git push origin feature: Pushes the local 'feature' branch to GitHub, preserving branch history on the remote server.

Question 2: Test Case Design Score: 10 Marks

Application Scenario: User Login Authentication System
Inputs: Username (Text field), Password (Masked input), Login Button (Submission trigger).
Functional Requirements: [FR1] Username must not be empty. | [FR2] Password must be at least 6 characters long. | [FR3] Valid username and password allow successful login. | [FR4] Invalid credentials display an error message. | [FR5] After 3 consecutive failed login attempts, the account should be locked.

Strategy Applied Test Design Techniques & Methodology

  • Equivalence Partitioning (EP): Partitioned inputs into valid classes (non-empty username, password ≥ 6, matching credentials) and invalid classes (empty strings, whitespace-only, password < 6, non-matching credentials).
  • Boundary Value Analysis (BVA): Evaluated boundary password lengths: 0 (empty), 1 (extreme low), 5 (just below boundary), 6 (minimum valid boundary), and 7+ (valid standard).
  • State Transition Testing: Evaluated progressive security states: Active (Count=0) → Fail 1 (Count=1, Warning) → Fail 2 (Count=2, Warning) → Fail 3 → State=LOCKED, plus locked-state rejection and counter reset on success.
  • Negative & Security Testing: Validated OWASP anti-enumeration generic error messaging and case sensitivity.
